What is this Data Structure Visualizer?

    
This is a free, browser-based tool for visualizing and debugging data structures written in Python. Unlike most visualizers, which only animate a fixed, pre-built algorithm, this tool runs your own code — paste any Python implementation of a binary search tree, an n-ary tree, a linked list, a graph, a heap, a stack, or a queue, along with driver code that exercises it, and it executes the real Python interpreter in your browser to trace exactly what your code does, line by line.

  

  

    
How it works

    
The tool uses Pyodide, a full CPython runtime compiled to WebAssembly, so your code runs as real Python — not a simulation or reimplementation. As execution proceeds, a line-level tracer inspects your live objects after every statement, automatically detects which variable holds your structure and what kind of structure it is, and reconstructs it by walking whatever attributes or contents your code uses. The result is a step-by-step debugger that shows the actual line executing, the live local variables in the current stack frame, the structure redrawn at every step, and the real traversal path highlighted as it moves through the structure.

  

  

    
Supported data structures

    
    
      
  • Binary search trees using left/right child attributes (or dict-style keys)
    • 
      
  • N-ary trees using a children list
    • 
      
  • Linked lists, singly or doubly, using next/prev attributes — cycles are detected and drawn
    • 
      
  • Graphs, either node objects exposing a neighbors/adj list, or a plain adjacency dict like {'A': ['B', 'C']}
    • 
      
  • Heaps and arrays — any plain list of numbers/strings, with an optional toggle to also view it as the implicit binary tree a heap represents
    • 
      
  • Stacks and queues — a list or collections.deque named accordingly, drawn as a vertical stack with a "top" marker or a horizontal queue with front/rear labels
    • 
    

    
Node values are read from common attribute names like val, value, data, key, or name. No special base class or library import is required — most conventional implementations work without modification.

  

  

    
Constraints — what your code needs to look like

    
Class names don't matter at all — a Node, TreeNode, or Vertex class all work identically, since detection is based on attributes an object has, not what it's called. What does have to match are the attribute and variable names below:

    

      
ThingMust be named one of

      
        
Binary childrenleft/right, l/r, left_child/right_child, leftChild/rightChild, lchild/rchild

        
N-ary childrenchildren, kids, child_nodes, or nodes (must be a list/tuple)

        
Linked list pointersnext/nxt/next_node/succ, optional prev/previous/prev_node/pred for doubly linked

        
Graph neighborsneighbors, neighbours, adj, adjacent, edges, links, or connections as a list on each node object — or a top-level dict mapping keys to lists of neighbor keys

        
Node valueval, value, data, key, item, label, name, or v

        
Structure/root variableroot, tree, bst, head, node, graph, g, start, heap, pq, arr, array, lst — at module level, inside a function, or as .root/.head/.top on a wrapper class

        
Stack / queue variablestack/stk/st for a vertical stack view; queue/q/fifo/dq, or any collections.deque regardless of name, for a queue view

        
"Current" node per stack framea local variable named self, node, current, cur, curr, temp, ptr, n, or root in that function

        
"Current" index (arrays/heaps/stacks/queues)a local variable named i, idx, index, j, k, or pos holding an integer in range

      
    

    
If your code uses none of these — a child attribute called kid1/kid2, a value stored under .age, a root variable called treeHead — the tool won't find a structure to draw. It fails silently rather than erroring; you'll just see "no structure detected." There's no configuration option to add custom names, so the fix is either renaming to match one of the conventions above, or extending the tool's source if you're self-hosting it. This covers most textbook and interview-style implementations, but not every possible naming scheme.
